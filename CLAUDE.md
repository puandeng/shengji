# 200 Card Game (Sheng Ji)

## Objective
A real-time, browser-based multiplayer implementation of **200分 / Sheng Ji**, the Chinese trick-taking card game. Four players in two fixed teams compete across multiple rounds; the attacking team tries to collect enough points from scoring cards (5s, 10s, Ks — 200 pts total in two decks) to hit the round threshold, while the defending team tries to deny them. Each round's winner advances their team's level; the first team to advance past Ace wins the match.

The goal of this project is to provide a clean, self-contained reference implementation playable over a LAN or the internet via a 4-letter room code — no accounts, no persistence, just open the page and play.

## Architecture
Monorepo with npm workspaces.

```
shengji/
├── server/   # Node.js + Express + Socket.io — authoritative game state
└── client/   # React 18 + Vite — UI and socket client
```

- **Server is authoritative.** All game logic (dealing, follow-suit validation, trick resolution, scoring) lives in `server/game/` and runs on the server. Clients only send intents (`game:playCards`, `game:callTrump`, …) and receive state snapshots.
- **Transport:** Socket.io rooms keyed by a 4-letter code generated by `RoomRegistry` (`server/game/Room.js`).
- **State:** in-memory only — no database. Rooms are deleted when empty.
- **Per-player views:** `GameState.toPlayerJSON()` strips other players' hands before sending, so a client only ever sees its own cards plus opponents' hand counts.
- **Scoring:** only the attacking team accumulates points. Defending team never scores — they only deny. Kitty belongs to whoever wins the last trick; if attackers win it, kitty points × (2 × number of cards in the winning play) are added to their score — single ×2, pair ×4, tractor of 3 pairs ×12.
- **Levels, not round counts:** each team holds a level (`teamLevels`, starting at `2`). The round winner advances 1–3 levels depending on the point margin; levelling past `A` wins the match. `MANDATORY_STOP_RANKS` (5, 10, K, A) cannot be skipped on a team's first visit.

## Game Flow
1. **WAITING** — players join via room code; host starts when 4 are seated (or fewer, with bots, under `DEV_MODE`).
2. **DEALING** — 2 decks + 4 jokers (108 cards) → 25 per player + 8 kitty. Cards are drip-fed one at a time via `game:cardDealt` every `DEAL_CARD_INTERVAL_MS` (120ms) so the client can animate the deal. Players may call trump with cards already in hand during this phase. `game:dealComplete` ends it.
3. **TRUMP_SELECTION** — 30s window. Players call trump with `game:callTrump` by showing cards: 1 rank card = strength 1, a rank pair = strength 2, a same-type joker pair = strength 3. Higher strength overrides a lower one; equal strength goes to the first caller. A joker-pair call sets `trumpSuit = null` (only trump-rank cards and jokers are trump that round). Players may `game:passTrump`; once all four pass, selection finalises immediately instead of waiting out the timer. On timeout with no call, `autoSelectTrump()` falls back to the first kitty card's suit. Declarer's team becomes attacker.
4. **KITTY** — declarer picks up the 8 kitty cards and discards 8 back.
5. **PLAYING** — trick-taking with multi-card plays: single, pair, tractor (consecutive pairs), and throw (1 single + 1 pair, 3 cards). All combo cards must share an effective suit. Must follow the lead suit if held. Trump order: big joker > small joker > in-suit trump-rank > off-suit trump-rank > trump suit by rank > lead suit > off-suit. A throw that gets beaten by the opposing team costs the throwing team 30 points.
6. **SCORING** — round ends when hands are empty. Attackers win if they collected ≥ `LEVEL_THRESHOLDS[trumpRank]` (80 for levels 2–K, 120 for A). The winning team advances 1–3 levels by margin (see the rules table). Loser of the round attacks next.
7. **GAME_OVER** — a team that advances past `A` wins the match.

## Game Rules Reference
| Rule | Value |
|---|---|
| Players | 4 (seats 0–3) |
| Teams | Seats 0&2 vs Seats 1&3 |
| Decks | 2 × 52 + 4 jokers = 108 cards |
| Cards per player | 25 |
| Kitty size | 8 |
| Point cards | 5 → 5pts, 10 → 10pts, K → 10pts |
| Total points | 200 |
| Round threshold | 80 (levels 2–K) / 120 (level A) — attacker must reach this |
| Scoring | Only attacking team accumulates points |
| Kitty | Goes to last-trick winner; if attackers win it, kitty pts × (2 × cards in the winning play) |
| Trump order | Big joker > small joker > in-suit trump-rank > off-suit trump-rank > trump suit by rank > lead suit > off-suit |
| Play shapes | Single, pair, tractor (consecutive pairs), throw (single + pair) — all one effective suit |
| Throw penalty | Throwing team loses 30 pts if the opposing team beats the throw |
| Trump call strength | 1 = rank card, 2 = rank pair, 3 = same-type joker pair; higher overrides, ties to first caller |
| Levels | Both teams start at `2`; round winner advances 1–3 levels |
| Level skips | Attackers ≥ threshold+80 → +3, ≥ threshold+40 → +2, else +1. Defenders: attackers held to 0 → +3, attackers < threshold−40 → +2, else +1 |
| Mandatory stops | 5, 10, K, A cannot be skipped on a team's first visit (`MANDATORY_STOP_RANKS`) |
| Match length | First team to advance past `A` |
| Trump declare timer | 30s |

## Socket Protocol

### Client → Server
| Event | Payload | Description |
|---|---|---|
| `room:create` | `{ name }` | Create a new room |
| `room:join` | `{ name, code }` | Join existing room |
| `room:start` | — | Start the game (host only) |
| `room:chat` | `{ message }` | Send chat message |
| `game:callTrump` | `{ cardIds[] }` | Call/override trump (1 card = single, 2 = pair or joker pair) |
| `game:passTrump` | — | Pass on calling trump |
| `game:discardKitty` | `{ cardIds[] }` | Discard 8 cards to the kitty |
| `game:playCards` | `{ cardIds[] }` | Play 1–N cards (single / pair / tractor / throw) |
| `room:newRound` | — | Start next round (host only) |
| `room:state` | — | Re-request the current snapshot (used on reconnect) |
| `game:declareTrump` | `{ cardId }` | **Legacy** — wraps `callTrump` with a single card |
| `game:playCard` | `{ cardId }` | **Legacy** — wraps `playCards` with one card |

### Server → Client
| Event | Description |
|---|---|
| `player:joined` | A player joined the lobby |
| `player:left` | A player disconnected |
| `game:started` | Game has started; dealing begins |
| `game:cardDealt` | One card dealt to this player (animated deal) |
| `game:dealComplete` | All 100 cards dealt; moves to `TRUMP_SELECTION` |
| `game:trumpCalled` | A trump call was made or overridden (includes the declaring cards) |
| `game:trumpSelected` | Trump finalised; declarer picks up the kitty |
| `game:kittyDiscarded` | Kitty cards discarded, play begins |
| `game:cardsPlayed` | Cards were played (trick in progress) |
| `game:cardPlayed` | **Legacy** single-card variant of `game:cardsPlayed` |
| `game:trickComplete` | Trick resolved (includes winner & scores) |
| `game:newRound` | New round started |
| `room:chatMessage` | New chat message |

## Conventions

### Code style
- **Indentation:** 4 spaces (note: existing files use 2 — match the surrounding file when editing)
- **Comments:** only when the "why" isn't obvious from the code
- **Server is authoritative** — never duplicate validation logic on the client; send an intent and trust the server response

### Collaboration (multiple Claude sessions / humans)
This repo is worked on by several people, often via parallel Claude Code sessions. Follow these rules to avoid stepping on each other:

1. **Always sync before starting work.**
   ```bash
   git checkout main && git pull --ff-only origin main
   ```
   Read `PLAN.md` to see what's already in flight before picking up a task.

2. **Never commit directly to `main`.** Always create a branch:
   ```bash
   git checkout -b feat/<short-description>
   ```
   Branch prefixes: `feat/`, `fix/`, `refactor/`, `docs/`, `test/`, `chore/`.

3. **Commits:** conventional commits (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`). Keep them small and focused; the commit body should explain *why*, not *what*.

4. **One task = one branch = one PR.** Don't bundle unrelated changes. If you discover a second issue, note it in `PLAN.md` and open a separate branch.

5. **Open a PR as soon as the branch has meaningful changes.**
   - Title: matches the conventional-commit style (`feat: add kitty animation`)
   - Body: what changed, why, how to test, and a link to the `PLAN.md` item it addresses
   - Mark as **Draft** if still in progress so others know not to review yet

6. **PRs require at least one approval before merging.** Do not self-merge unreviewed PRs. If a reviewer requests changes, push fixups to the same branch — don't open a new PR.

7. **Merge strategy:** squash-merge into `main`. Delete the branch after merging.

8. **Rebase, don't merge, when updating a branch from main:**
   ```bash
   git fetch origin && git rebase origin/main
   ```
   This keeps history linear. Force-push with `--force-with-lease` (never plain `--force`).

9. **Update `PLAN.md` as you go.**
   - Mark items in-progress when you start (add your name/session id)
   - Mark items done in the same PR that completes them
   - Add newly discovered todos to the bottom rather than silently dropping them

10. **Update `CLAUDE.md` when you change architecture, conventions, or the socket protocol.** If a future session would be misled by the current `CLAUDE.md`, fix it in the same PR. Treat `CLAUDE.md` as load-bearing documentation, not a README afterthought.

11. **Don't rewrite history on shared branches.** Rebasing your own unmerged feature branch is fine; rewriting `main` or anyone else's branch is not.

## Prerequisites
- Node.js 18+
- npm 9+

## Quick Start
```bash
# install everything (uses npm workspaces)
npm run install:all

# run server + client together
npm run dev
```

Or run them separately:
```bash
# Terminal 1
cd server && npm run dev    # → http://localhost:3001

# Terminal 2
cd client && npm run dev    # → http://localhost:5173
```

Then open `http://localhost:5173`, create a room, and share the 4-letter code with 3 friends.

### Environment
- `server/.env` — `PORT` (default 3001), `CLIENT_URL` (CORS origin, default `http://localhost:5173`), `DEV_MODE` (any truthy value lets a room start with <4 players and fills empty seats with bots; exposed to the client via `GET /config`)
- `client/.env` — server URL for the socket connection

### Build / Production
```bash
npm run build    # builds the client (Vite)
npm run start    # runs the server (node)
```
